# Phase 7.0 — Authentication & Authorization

## What is Authentication?

Authentication is the process of **verifying the identity of a user**.

It answers the question:

> **"Who are you?"**

The server checks whether the credentials provided by the user are valid.

### Examples
- Login with Email & Password
- Login with Google
- Login with GitHub
- Login with OTP

If the credentials are correct, the server knows the user's identity.

---

## What is Authorization?

Authorization is the process of **checking what an authenticated user is allowed to do**.

It answers the question:

> **"What are you allowed to do?"**

After authentication is complete, the server verifies the user's permissions or role before allowing access to a resource.

### Examples

| User Role | Permissions |
|-----------|-------------|
| Admin | Create, Update, Delete Users |
| Teacher | Create Notes |
| Student | View Notes |

Authentication happens **first**, followed by authorization.

---

# Authentication vs Authorization

| Authentication | Authorization |
|----------------|---------------|
| Verifies user identity | Verifies user permissions |
| Answers **Who are you?** | Answers **What are you allowed to do?** |
| Happens first | Happens after authentication |
| Example: Login | Example: Checking if a user can delete a project |

---

# Why Don't We Send Passwords With Every Request?

Suppose a user logs in.

Instead of sending:

```http
Email
Password
```

with every API request, the server verifies the credentials once and returns a **JWT Token**.

Reasons:

- More secure
- Faster
- Reduces repeated authentication
- Password is not transmitted repeatedly

# Authorization Header

Every protected request includes the JWT inside the HTTP Authorization header.

```http
Authorization: Bearer <JWT_TOKEN>
```

The server verifies the token before processing the request.

---

# What is JWT?

JWT (JSON Web Token) is a secure token generated by the server after successful authentication.

Instead of sending the password repeatedly, the client sends this token with every protected request.

The server validates the token to identify the user.

---

# Is JWT Used for Authentication or Authorization?

JWT helps with **both**.

## Authentication

The server verifies the JWT and identifies the user.

Example:

```json
{
  "sub": "user123"
}
```

The server now knows which user is making the request.

---

## Authorization

JWT can also contain user roles or permissions.

Example:

```json
{
  "sub": "user123",
  "role": "admin"
}
```

The application checks these claims to decide whether the user is allowed to perform a particular action.

# Key Takeaways

- Authentication verifies **who the user is**.
- Authorization verifies **what the user is allowed to do**.
- Authentication always happens before authorization.
- Passwords should **never** be sent with every API request.
- After successful login, the server returns a **JWT Token**.
- The client sends the JWT in the **Authorization** header using the Bearer scheme.
- JWT is used for both **authentication** and **authorization**.
- The server validates the JWT before allowing access to protected resources.
